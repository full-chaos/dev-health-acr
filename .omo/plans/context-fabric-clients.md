# context-fabric-clients - Work Plan

## Objective

Deliver CHAOS-3007 and CHAOS-3010 as one ordered implementation: first make `acr-mcp` federate bounded local CodeGraph evidence with the authoritative hosted context packet, then ship supported OpenCode, Claude Code, Codex, and Cursor packages that consume only the released sidecar.

## Scope

- CHAOS-3007 adds the generic `LocalIndexProvider`, the CodeGraph adapter, additive MCP federation contracts, local evidence expansion, diagnostics, privacy controls, and mixed hosted/local verification.
- CHAOS-3010 adds client-native packages under `clients/{opencode,claude-code,codex,cursor}`, shared conformance under `clients/conformance`, signed distribution inside existing `acr-mcp` archives, clean installation/update/uninstall, and real-client verification.
- CHAOS-3007 must merge and pass default-branch CI before the CHAOS-3010 implementation branch is cut.
- CHAOS-2946 and CHAOS-2941 are already merged and are not reopened, modified, or reimplemented by this plan.

## Boundaries

- CodeGraph owns repository parsing, graph/index creation, refresh, storage, language support, and graph-query execution. ACR consumes an existing index read-only.
- Production code may invoke only fixed CodeGraph JSON commands: `status --json`, `query --json`, `callers --json`, `callees --json`, `impact --json`, `affected --json`, and `files --json`.
- Production code must never invoke CodeGraph `init`, `index`, or `sync`; read CodeGraph SQLite directly; parse `codegraph explore` text; or maintain another parser, graph, vector index, or local code store.
- Supported CodeGraph versions are `>=1.2.0,<2.0.0`; additive JSON fields are tolerated, while missing required fields and incompatible versions degrade safely to hosted-only behavior.
- Local-index configuration remains outside `sidecar.Config.Validate()`. Invalid, missing, stale, or incompatible local state must never prevent the existing hosted bootstrap from succeeding.
- Hosted `ContextPacket` remains authoritative and unchanged. The only wire changes are additive optional MCP v1 fields; OpenAPI is not applicable and must remain unchanged.
- Raw source, complete CodeGraph output, index contents, local filesystem roots, credentials, and arbitrary local graph payloads are never sent to the hosted API.
- Clients launch `acr-mcp serve` through supported client mechanisms. They must not call hosted Context Fabric, read credentials, query CodeGraph, rank evidence, enforce authorization, expand evidence, or implement separate token budgets.
- `record_episode` remains absent by default. Pre-plan invocation ships disabled and is enabled only through explicit installer/user opt-in.
- Client packages are bundled inside existing signed `acr-mcp` archives. No new release artifact type, unsigned installer channel, or public publication is introduced.

## Waves

- **Wave 0, contract discovery:** pin the CodeGraph CLI contract, fixtures, compatibility range, and architecture decision.
- **Wave 1, parallel foundations:** add the provider boundary/fake contract suite, isolated local configuration/hardened runner, and additive MCP contracts.
- **Wave 2, adapter and diagnostics lane:** implement CodeGraph JSON consumption, then add diagnostics against the proven adapter.
- **Wave 3, federation behavior:** complete freshness/error classification and the deterministic merge, budget, ID, provenance, cache, and evidence-routing behavior in parallel.
- **Wave 4, CHAOS-3007 proof and closeout:** prove privacy, mixed MCP behavior, and documentation before declaring CHAOS-3007 implementation-ready.
- **Wave 5, CHAOS-3010 reference lane:** define one shared client contract, then implement OpenCode as the serial reference consumer.
- **Wave 6, client parallelism and closeout:** build Claude Code, Codex, and Cursor in parallel; then run shared conformance and release packaging in parallel before documentation and closeout.
- Maximum concurrent implementation workers: four. Each worker owns one task-scoped worktree; dependent branches are cut only after blockers merge.

## Success criteria

- `acr-mcp` consumes an existing CodeGraph `>=1.2.0,<2.0.0` index through fixed bounded JSON commands without creating, refreshing, mutating, or directly reading the index.
- Missing, stale, dirty, mismatched, incompatible, malformed, oversized, or timed-out CodeGraph state never breaks valid hosted retrieval and is represented by deterministic safe warnings/status.
- One MCP response can contain an unchanged authoritative hosted packet plus clearly distinguished generic local context within the caller’s packet-content item/token/serialized-byte budget.
- Packet-content accounting applies caller maxima only to hosted `ContextPacket` content plus local evidence content; MCP envelope fields, `federated_budget`, and `rendered_markdown` are outside those maxima and remain bounded independently by existing MCP validation.
- Hosted-only requests retain the full caller packet-content budget; mixed requests reserve no more than one quarter for local content, hosted uses the remainder, and local content is trimmed first on packet-content overflow.
- Local evidence IDs use `local:codegraph:v1:<sha256>`, are deterministic and disjoint from hosted IDs, and expand locally through the bounded lifecycle-owned locator cache.
- `indexed_commit` is omitted when CodeGraph does not provide it, with `indexed_commit_unknown`; no commit/ref is inferred from SQLite, current HEAD, or unrelated metadata.
- Captured hosted traffic proves raw source, complete graph/index data, local roots, local locators, credentials, and CodeGraph payloads remain local by default.
- MCP v1 request/response additions are optional and contract-first across Go DTOs, validators, decoders, JSON Schemas, MCP manifest, embedded schemas, examples, contractcheck mappings/definitions, and parity tests; canonical OpenAPI remains unchanged.
- OpenCode, Claude Code, Codex, and Cursor packages register exactly `acr-mcp serve`, share the same context/evidence/degraded workflow, contain no credentials or direct runtime logic, and keep pre-plan invocation and writeback disabled by default.
- OpenCode’s TypeScript plugin owns only bounded `acr-mcp doctor --offline` status; it never calls Context Fabric, CodeGraph, or MCP context/evidence tools directly.
- All clients pass mandatory package, fixture, conformance, install, update, and uninstall tests; OpenCode, Claude Code, and Codex pass real/headless smoke, while Cursor real smoke is conditional only on installed-client availability.
- Client assets are contained inside the existing signed `acr-mcp` archives, preserve the current artifact matrix/manifest type, and are covered by deterministic checksums, signatures, tamper detection, and private release policy.
- Numbered-task closeout uses only Tasks 1-19 evidence; live-CodeGraph proof is produced later by F2 and is required by F5, preserving acyclic execution.
- F1-F5 approve on fresh evidence, then the user explicitly accepts before CHAOS-3007/3010 status changes or any completion declaration.
